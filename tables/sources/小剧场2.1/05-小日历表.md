# 小日历表

## sourceData.note

固定维护7天日历窗口：今天、明天、后天、3天后、4天后、5天后、6天后。今天日期必须取自全局数据表第 1 行“当前时间”的日期部分（YYYY-MM-DD）。无法读取该值时，禁止改用现实日期、系统日期或自行推断日期；其他6天围绕今天连续向后推算。

# 字段规则
- 日期：必须使用 YYYY-MM-DD 格式。今天行必须与全局数据表当前时间的日期部分完全一致。其余日期必须围绕今天连续排列。不得跳日、重复、缺失或越界。跨月、跨年时必须按真实历法连续计算。
- 星期几、月份几天：前端派生，ai不填写。
- 节日：节庆、纪念日、校历/职场/城镇/宗教/世界观节日；没有可留空，不要为了填满而每天硬造节日。
- 大事件：每天必须填入一个具体的、有明确名称的公共事件或可见变化，不能使用任何表示“一切照旧”的抽象短语。严格禁止出现“常态教学”“照常上课”“正常上班”“秩序正常”“普通通勤”“日常运转”“新周开始”等直接表示无事的词汇。大事件应理解为“这个世界在这一天发生的一件值得被记录的事情”，而不是普通公共事务记录。事件应具有明确主题、具体场景和当天特色，能够让公众产生参与、观察或讨论的理由。优先生成具有事件感的公共事项，例如具有明确背景、独特安排、特殊变化、限定性质或公共影响的事项。事件可以规模很小，但应具备明确的当天性和记忆点。普通、重复、缺乏变化的常规事项，不应优先作为大事件。日常维护、例行检查、普通调整等内容可以作为背景，但不应默认成为大事件。只有当其本身造成明显公共变化、具有特殊背景或形成独特场景时，才适合作为当天事件。事件选择时应避免过度依赖当前剧情中的核心元素，不应因为正文存在某个主题，就默认该主题成为日历中的主要事件来源。世界观中的核心元素可以影响事件出现概率，但不能覆盖整个日历窗口。日历记录的是整个世界的公共时间，而不是某个角色、组织、职业或兴趣圈子的活动安排。大事件应从整个生活环境中自然产生，综合考虑社会、地点、季节、群体生活和世界状态，使不同日期呈现不同来源和不同氛围。7天内的大事件不得集中围绕同一种主题、同一个群体或同一种活动逻辑展开。除非世界观存在明确的持续性公共事件，否则单一主题不应占据多数日期。

- 状态：只能逐字填写完整字面值 `上班/上学` 或 `放假`。
- 天气：只能逐字填写 晴、阴、多云、小雨、大雨、雷雨、小雪、大雪、雾、风、沙尘、极端天气，可以实时根据世界观当地环境用数据库填写天气。
- 与今天的关系：只能逐字填写 今天、明天、后天、3天后、4天后、5天后、6天后；固定7行中这7个关系应各出现一次，不应重复，不应缺失。
- 内容：约 200 字，只介绍当天公共触发点的背景、含义、公共安排、参与方式、环境变化和可见影响；禁止写主角计划、NPC计划、私人行程、约会安排、秘密事件、角色心理或剧情推进。

# 填表责任
本表用于维护世界时间窗口和界面可信度。输出前必须检查日期连续性、枚举取值、7个关系是否完整、内容是否越过公共日程边界。不要为了显得丰富而编造角色私人行程；宁可少写，也不要错写。

# 日期与越界规则
1. 日期必须围绕“今天”连续排列。例如今天是 2026-05-16，则 6天后应为 2026-05-22。
2. 不允许出现超出实际月份天数或不符合当前历法的越界日期。若今天处在月末，必须跨到下个月。
3. 今天不应该是更新一次日历表格就变一天；必须以全局数据表当前时间为锚点保持一致。

# 内容方向
每天都必须有可被感知的世界变化或公共触发点，决不允许出现没有事件的日子。常态运转本身不是事件，只有制度、环境、公共活动、天气影响、资源安排或世界观状态发生可见变化时才构成大事件。日历只提供世界层面的公共日程，不提供主角行程表。可以写群体性参与方式，不能写具体角色如何参与。事件必须贴合世界观、季节、地点、组织和生活圈，并且让当天与其他日期产生明显区别。生成事件时，不要只考虑当前剧情最突出的元素，而应优先考虑“这个地方在这一天整体发生了什么”。日历需要呈现完整世界的公共生活，而不是围绕某个角色关注点生成附属活动。事件来源应保持自然分布，使7天窗口中的公共生活具有变化感和层次感。事件不要求规模巨大，但应具有鲜明特点和当天记忆点。内容重点不是解释事件的重要意义，而是呈现当天具体发生了什么，以及它如何影响公共环境、人群和生活状态。节日、大事件、天气、状态和内容要互相支撑，不得出现逻辑冲突（例如雷雨天写露天活动正常举行且无人受影响）。当某天确实缺乏天然事件时，必须主动从天气变化、设施状况、外部通知、社会动态、地方生活或世界观背景中创造一个微小但合理、具有事件感的公共触发点，使每一天都具有独一无二的叙事背景。

# 更新规则
1. 本表必须保持7行。少于7行时补齐缺失关系；多于7行时删除多余、重复或已离开窗口的行。
2. 禁止为了刷新内容整表删除后重建。今天只推进1天时，删除离开窗口的旧日期，插入新进入窗口的新日期，其余日期保留节日、大事件、状态、天气和内容，只更新与今天的关系。
3. 若今天发生大跨度变化，直接UPDATE现有7行为新窗口；不要删除7行再重建。与今天的关系虽然不再由数据库 UNIQUE 强制，但仍必须在7行中保持完整且不重复。
4. 只允许删除多余、重复、越界、坏数据或离开窗口的单行。

## sourceData.initNode

初始化时插入且只插入7行。先读取全局数据表当前时间的日期作为今天，再生成连续7天窗口。7行关系必须各出现一次、不重复、不缺失；日期连续。

## sourceData.deleteNode

禁止整表删除。只允许删除离开7天窗口的旧日期、多余行、重复关系行、日期越界行或明显错误行。常规跨一天最多删除离窗旧日，再插入新入窗日期。删除后必须补回7行，不允许让小日历表长期少于7行；补回后7个关系仍应完整且不重复。

## sourceData.updateNode

当全局数据表当前时间的日期、世界阶段、节庆安排、公共事件、天气影响或生活节奏出现可见变化时更新。今天行日期必须始终等于全局当前时间的日期。仍留在新窗口内的旧日期尽量保留原节日、大事件、状态、天气和内容，只更新必要字段；新进入窗口的日期才生成新内容。

## sourceData.insertNode

仅在少于7行、缺少某个关系值，或日期推进导致新日期进入7天窗口时新增。常规跨一天只插入新进入窗口的那一天；不得为了刷新内容插入第8行。

## sourceData.ddl

```sql
CREATE TABLE small_calendar_days ( -- 小日历表
  row_id INTEGER PRIMARY KEY, -- 行号
  date_text TEXT, -- 日期
  weekday_text TEXT, -- 星期几
  festival_text TEXT, -- 节日
  major_event TEXT, -- 大事件
  day_status TEXT, -- 状态
  weather_text TEXT, -- 天气
  today_relation TEXT, -- 与今天的关系
  day_content TEXT, -- 内容
  month_days TEXT -- 月份几天
);
```
