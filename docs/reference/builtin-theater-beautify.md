# 内置小剧场默认美化与图片

## 边界

系统商店通过 `systemShop` scene 追加在小日记之后，绑定「系统商店」单行七列表。正式表源为 `tables/sources/小剧场2.1/07-系统商店表.md`，已有聊天通过现有模板导入／合并加入该表；页面本身不创建模拟行或商品。

市场沿用内置挂载、表更新订阅、主题、物理表导航和编辑桥，购买一次提交点数、背包与售空标记；刷新扣 10 点并申请下次填表换货，售空不自动补货。确认时读取最新数据，写入走现有行更新 API。使用道具仅追加酒馆输入草稿，不发送、不消耗。AI 填表期间只显示约定的页面底部提醒，不加互斥。首页与页面标题沿用系统商店表名。底部的标题栏与布局保持不变，导航动作继续由底部宿主限制，购买、刷新、放弃、使用与 App 一致。同一行未变时跳过重复解析和重绘，更新内容时保留滚动位置。视觉和真实宿主验收由用户进行。

广场、论坛、小日记、直播的默认页面基于用户提供的「0813 专属美化」适配。入口仍为物理表路由；已应用的内容预设优先级、工坊导入、匹配和绑定不变。没有把用户的 JSON 包写入工坊，也没有带入作者的个人图片。

场景定义的可选 `mountBuiltin(context)` 由[原生页面运行时](../../modules/phone-theater/builtin/runtime.js)挂载。通用小剧场负责场景发现、编辑桥和不可用回退；四个页面只负责自己的 DOM 与展示交互。小日历继续使用原有场景，仅更新配色和全局主题。

## 展示与生命周期

- [只读快照](../../modules/phone-theater/builtin/model.js)保留物理行索引，不改写原始表格。广场、论坛、日记从新到旧展示；日记按角色分组并保留左右头像／正文布局。直播仅消费一条记录。
- 新页面使用 Yuzi 独占 class，字体和字号消费主设置的字体与可读文本缩放变量；字体库覆盖范围包含内置正文与控件，但排除图标与等宽文本，不穿透工坊页面。明暗模式订阅主设置，不保留页面独立开关。
- 广场和日记通过[内置导航适配](../../modules/phone-theater/builtin/navigation.js)复用标准标题栏。论坛列表仅保留一行导航：左右箭头夹住“发现／关注”，不另加“论坛表”标题；详情保持现有顶部高度，作者头像与姓名紧邻返回箭头，关注按钮靠右。广场、论坛和日记的底部留白跟随 Home 安全区，宿主已腾出 docked 空间时不重复预留。
- 直播不增加独立标题栏，主播栏、标题和概述保留原始布局；关闭与底部切表／编辑入口保留，不增加底部安全区，暂停／继续与生图按钮仍位于偏右上区域。
- 小日记标题栏使用随主题变化的不透明背景并关闭背景模糊，避免黑色外壳在圆角内晕染；不修改全局手机外框、阴影或小日历。
- 退出页面会清理事件订阅、头像 lease、图片控件和临时预览。直播轮播在文档或手机不可见时暂停，返回后恢复；不生成模拟弹幕或虚构互动数值。
- 广场、论坛、日记的社交控件保持装饰；直播的关注、点赞动效和借用表情／礼物／分享的原导航行为保留。

## 生图

[共用表格图片宿主](../../modules/image-generation/table-image-host.js)提供原有稳定归属、转换、超时和图片保存链路。内容预设与内置页面通过不同入口适配接入，不互相依赖绑定状态。

| 画布 | 取词字段 | 构图说明 |
| --- | --- | --- |
| 广场 image | 发帖账号名、图片描述 | 2:1 |
| 广场 video | 发帖账号名、视频描述 | 2:1，生成的仍是图片 |
| 论坛 cover | 帖子正文 | 16:10，列表和详情共用 |
| 直播 background | 剧情舞台概述 | 当前背景画布实际宽高 |

广场仅在对应描述有效时显示对应画布，双画布独立生成。内置页面先组合指定字段并扫描现有姓名映射，再追加构图说明，随后进入共享的可选 Tag 转换与智慧姬流程。不额外读取标题、评论等字段，不把提示词中的尺寸文字当作接口强制尺寸参数。

广场的 image／video 和论坛列表／详情的 cover 在没有图片时保留原占位比例；生成或回读到图片后，展示画布按图片原本的宽高比增长，不再用固定比例和 `cover` 裁切。长图由页面正常滚动查看，广场同帖的两张图片各自适配。直播仍是固定舞台背景，不参与这项展示调整。

生图设置的 `enabled` 是总开关；`qqEnabled` 默认 true，保持旧配置行为；`theaterEnabled.square/forum/live` 默认 false，分别控制三个内置场景。作者画布仍使用原 `tableDisplayEnabledBySheetKey` 设置，不改变旧开关含义。关闭入口不会隐藏或删除已经生成的图片。

[图片控件](../../modules/phone-theater/builtin/image-controller.js)让论坛两处画布共享请求状态和结果，返回列表时释放旧详情画布。控制器必须在 detached 路由准备阶段绘制开关、图标与缓存图片，不以 `isConnected` 跳过首次绘制；生命周期和聊天作用域保护保持生效。生图入口沿用 QQ 的 Font Awesome 魔法棒／重生成图标及忙碌状态，背景透明，不显示文字胶囊。旧读取晚到不得覆盖新生成的结果；表格更新后重新绑定当前内容，不持有旧行闭包；失败保留旧图。直播生成后隐藏标题、标签、概述及默认人形，保留主播栏、弹幕和底部操作栏，不增加图片查看弹窗。

图片归属使用聊天作用域、物理表、稳定内容标识和画布。广场优先使用帖子 ID，缺失时使用账号／标题／时间组合；论坛使用账号／标题／时间／分区组合；直播使用直播间名。空的可选身份字段编码进组合标识，不使用行位置或提示词作身份。身份重复时拒绝生成；身份字段改变会成为新归属，不猜测或自动迁移旧图。

广场和论坛通过[共享图片查看内容](../../modules/ui-runtime/media-viewer-content.js)复用 QQ 的图片组件，并挂载到已有的小手机临时层；边框、标题栏和卡片底不再围住图片。这个无边框预览将长图完整缩放到可见区域，图片替代文字仍保留，但不显示底部描述；QQ 自己的查看界面不变。直播没有点击背景图的预览入口。

## 广场外观与头像

广场名称、签名、头像和背景按聊天保存在 `theaterProfiles`，最多 100 个聊天。头像与背景导入采用顶部同一行的同尺寸 SVG 图标按钮，图片直接导入，不裁剪、不压缩，单文件上限 8 MB。文件经现有外观 Blob codec 进入 IndexedDB，宿主设置仅保存引用；不使用 localStorage 或有 TTL 的缓存存用户文件。

顶部优先使用用户导入头像，其次 QQ 自己的头像／宿主用户头像。广场发帖者、日记角色按姓名唯一匹配 QQ 联系人头像；匹配不到则显示文字头像。论坛始终使用首字头像。

## 回归入口

- `node scripts/check-theater-builtin-behavior.cjs`：倒序与原行身份、独立画布字段、可选身份字段。

保留的脚本由现有 `npm run check` / `check:ci` 发现。内置生图入口的开关、提示词组合与持久回读，以及页面样式、加载／重生成状态、图片比例和预览清理，改为按相关改动人工验收；不再自动启动浏览器做页面回归。发布前仍需按项目流程运行 lint、相关回归和 build，最终视觉验收由用户进行。
